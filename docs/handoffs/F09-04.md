## Kapatılan bypass

F09-02 öncesi/sonrası public booking RPC'leri Supabase `anon` rolüne doğrudan execute veriyordu. Bu yüzden saldırgan Worker'ı atlayıp PostgREST RPC yüzeyinden public katalog/slot/create/recovery çağrıları yapabiliyordu. F09-04 eski raw public RPC grant'lerini `anon` ve `authenticated` rollerinden geri aldı; dış public yüzey artık yalnız guarded RPC'lerden geçer.

## Uygulanan sınır

1. Worker-only `PUBLIC_BOOKING_GATE_SECRET` kullanılır. Worker raw secret'i guarded RPC'ye proof olarak verir; PostgreSQL config tablosunda yalnız SHA-256 hash saklanır. Secret yoksa Worker DB çağrısından önce fail-closed davranır.
2. Worker bir günlük, imzalı, HttpOnly `yzt_public_client` cookie üretir. Actor anahtarı bu pseudonymous client ID'den HMAC-SHA-256 türetilir. Raw cookie DB'ye gönderilmez.
3. Network anahtarı `CF-Connecting-IP` üzerinden IPv4 için `/24`, IPv6 için `/64` coarse prefix'e indirgenir ve HMAC-SHA-256 ile hashlenir. Raw IP DB'ye gönderilmez.
4. PostgreSQL fixed-window sayaçları actor + network, create için ek olarak business boyutunda atomik uygulanır.
5. Varsayılanlar: read actor 120/dk, network 1200/dk; create actor 6/10dk, network 60/10dk, business 30/10dk; recovery actor 30/5dk, network 300/5dk.
6. Rate limit RPC hatası Worker'da HTTP `429` + `Retry-After` ve yapılandırılmış `PUBLIC_BOOKING_RATE_LIMITED` cevabına çevrilir.
7. Aynı başarılı booking'in aynı recovery/idempotency bootstrap ile güvenli tekrarı create bütçesini yeniden tüketmez ve mevcut appointment sonucunu döndürür.
8. Guarded public create, üst request yanlışlıkla authenticated JWT context taşısa bile nested booking command provenance'ını `public` tutar. Bu hardening recovery zincirinin `booking_commands.source='public'` invariantını korur.
9. Rate counter'larda yalnız türetilmiş hash'ler tutulur. `updated_at` index'i ve request-path bounded prune ile 48 saatten eski sayaçlar çağrı başına en fazla 500 satır temizlenir; rotatable actor churn tarihsel tabloyu sınırsız büyütmez.
