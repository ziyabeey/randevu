## Tespit edilen bypass

Main'de public booking Worker akışı `create_public_appointment_with_recovery` RPC'sini anon Supabase anahtarıyla çağırıyor. F09-02 migration'ı bu RPC'ye `anon` execute grant veriyor; Faz 6'nın eski `create_public_appointment` RPC'si de anon'a açık. Bu nedenle saldırgan Worker rate-limit/challenge kontrollerini tamamen atlayıp Supabase PostgREST RPC'ye doğrudan yazabilir.

## Seçilen güvenlik modeli

F09-04 bu sınırı üç katmanla kapatacak:

1. `PUBLIC_BOOKING_GATE_SECRET`: yalnız Worker environment'ında raw olarak bulunacak; DB yalnız SHA-256 hash saklayacak. Public read/create/recovery için yeni guarded RPC'ler bu proof olmadan çalışmayacak. Eski raw public RPC'lerin anon execute yetkisi geri alınacak.
2. Worker'ın imzaladığı HttpOnly `yzt_public_client` proof cookie'si: istemci kimliği olarak kullanılacak; cookie içeriği server HMAC ile doğrulanacak. DB'ye raw cookie veya IP gönderilmeyecek.
3. PostgreSQL'de atomik fixed-window sayaçları: actor + coarse network + hedef işletme boyutları birlikte uygulanacak. Böylece yalnız IP'ye dayanılmayacak ve ortak ağlarda tek kullanıcı bütün ağı kilitlemeyecek.

## Varsayılan limit hedefleri

- Public read: actor 120/dk, network 1200/dk.
- New booking intent: actor 6/10dk, network 60/10dk, business 30/10dk.
- Recovery: actor 30/5dk, network 300/5dk.

Sınırlar DB config tablosundan değiştirilebilir olacak. Aynı başarılı booking'in aynı idempotency/recovery bootstrap ile güvenli tekrarı create rate-limit bütçesine takılmayacak.

## Kabulte kanıtlanacaklar

- Worker bulk create 429 + `Retry-After` döndürür.
- Aynı ağdaki farklı signed actor'lar actor limitini birbirinden bağımsız kullanır; network limiti daha geniştir.
- Raw `create_public_appointment` ve `create_public_appointment_with_recovery` anon tarafından doğrudan çağrılamaz.
- Guarded RPC doğru server proof olmadan rezervasyon oluşturamaz.
- Safe idempotent retry rate-limit dolu olsa bile mevcut appointment sonucunu döndürür; yeni appointment yaratmaz.
- Public kapalı işletme ve geçersiz hizmet/personel mevcut güvenlik doğrulamalarını korur.
- Raw IP, signed cookie veya gate secret rate-counter tablolarına/log payload'ına yazılmaz.

## Kapsam dışı

Turnstile/CAPTCHA gibi üçüncü taraf challenge F09-04 için zorunlu varsayılmayacak; server-signed proof + çok boyutlu rate-limit yeterli değilse sonraki hardening olarak eklenir. Gerçek staging/production abuse yük testi F09-05/F17 kapsamındadır.
