## Run and interpretation

```sh
node --test --experimental-strip-types tests/f17-auth-calendar-hop-receipt.test.mjs
```

The existing `npm run test:http` discovery includes this test. It imports the actual `worker/app.ts`, so the measured calendar is the live F11 group-aware V2 handler, not the superseded legacy route.

The observer intercepts only a fixed synthetic Supabase origin and allowlisted read endpoints. There is no network fallback. It records invocation/completion order, HTTP status, total calls and overlapping fetch promises. URLs, parameters, cookies, token values, bodies and exception text are not retained in the report.

Authenticated session read, initial calendar read and an identical repeated calendar read are observed separately. Failure checks cover anonymous access, recovery sessions, revoked membership, Auth unavailability and calendar RPC failure. The numeric `F17_HOT_PATH_RECEIPT` is emitted only after these checks succeed and includes actual checkout identity plus source SHA-256 digests.

Local observer tests can run without loading the application dependencies:

```sh
node --test --test-name-pattern='trace recorder' tests/f17-auth-calendar-hop-receipt.test.mjs
```

This filtered command tests the recorder only. It does not execute product integration and must never be reported as a full Worker PASS. Full exact-candidate CI must execute all product callbacks and emit the numeric receipt before accepting this child.

## Evidence boundary

Upstream responses and their equal scheduling are synthetic. Overlap waves describe fetch-promise overlap, not browser or real network critical-path latency. Counts measure Worker-to-Supabase HTTP calls, not SQL queries inside RPCs.

This covers existing authenticated reads with an empty calendar fixture. Login, token refresh, user switching, real browser bootstrap/polling, nonempty-load capacity, hosted p50/p95 and delivery are not measured. The receipt marks latency `NOT_MEASURED` and p50/p95 as null, never zero. No speed improvement or final F17/MVP acceptance follows from this measurement.

The remaining F17 performance step is a release-candidate hosted/browser trace and p50/p95 measurement using synthetic tenants, then a risk-based decision about optimization. Do not bypass authentication or membership checks to reduce the measured counts.
