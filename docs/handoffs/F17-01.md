# F17-01 devir — geliştirme ve staging ortamı

Durum: **Repo-side hazırlık main'de; gerçek Supabase staging kuruldu ve ACL hardening canlıda doğrulandı; canlı kabul dış credential provisioning'i nedeniyle engelli.** Gerçek staging workflow ilk kez probe edildi ve GitHub `staging` environment provisioning'i eksik olduğu için fail-closed durdu. Cloudflare + Resend + gerçek staging workflow/smoke zinciri doğrulanmadan `Tamamlandı` sayılmaz.

- Cloudflare `staging` environment sözleşmesi ve `npm run build:staging`.
- Manual `Staging deploy` GitHub Actions workflow'u.
- Supabase migration push sırası.
- Server-side test Auth owner bootstrap'ı.

- Secret değerleri repo/PR/handoff içine yazılmaz; workflow yalnız secret isimlerini sözleşme olarak taşır.
- CI hosted Supabase'in `extensions` pgcrypto yerleşimini, API rol grant'lerini ve function default ACL davranışını taklit eder.
- Staging Supabase ref/URL ve fixture owner email'leri public workflow metadata'sıdır; owner parolaları her run'da rastgele üretilip GitHub masking'e eklenir. Böylece dışarıdan provision edilmesi gereken değer sayısı 17'den 11'e düşürülmüştür.

## Security advisor sınırı

- `RLS enabled but no policy` INFO kayıtları capability/outbox/config/rate-limit tablolarındaki bilinçli deny-all doğrudan tablo modelidir; tek başına açık sayılmaz.
- Server-secret veya opaque capability ile bilinçli anon EXECUTE verilen SECURITY DEFINER wrapper'lar advisor tarafından genel uyarı olarak listelenebilir; kabul, explicit ACL matrisi + uygulama secret/token kontrolüne dayanır.
- `btree_gist` extension'ın `public` şemasında olması ayrı bir advisor uyarısıdır. Bu F17-01 ACL blocker'ında extension relocation yapılmaz; appointment exclusion constraint riskine karıştırılmadan ayrı değerlendirilir.
- `touch_updated_at` mutable search_path blocker'ı PR #18 ile kapanmıştır.
