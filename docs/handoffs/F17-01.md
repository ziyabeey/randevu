## GitHub `staging` dış secret contract

Dışarıdan yalnız şu 4 secret gerekir:

- `CLOUDFLARE_API_TOKEN`
- `SUPABASE_DB_PASSWORD`
- `SUPABASE_ADMIN_KEY`
- `RESEND_API_KEY`

Secret değerleri Git, PR, handoff veya sohbet içinde tutulmaz.

Workflow tarafından türetilen/üretilen değerler:

- `CLOUDFLARE_ACCOUNT_ID` — `wrangler whoami --json` ile tek hesap üzerinden çözülür.
- `STAGING_SUPABASE_PROJECT_REF`, `SUPABASE_URL`, modern publishable Supabase key ve fixture owner e-postaları — workflow metadata.
- `STAGING_DATABASE_URL` — `SUPABASE_DB_PASSWORD` ham secret'ından workflow içinde percent-encoded session-pooler URL olarak üretilir.
- `STAGING_OWNER_A_PASSWORD`, `STAGING_OWNER_B_PASSWORD` — her run'da rastgele üretilir ve maskelenir.
- `PUBLIC_BOOKING_GATE_SECRET`, `NOTIFICATION_DISPATCH_SECRET` — her run'da rastgele üretilir; DB yalnız SHA-256 hash'lerini tutar, aynı raw değerler o run'ın Worker runtime'ına gider.
- `STAGING_APP_ORIGIN` — generated Worker adı + Cloudflare Workers subdomain cevabından türetilir.
- `MANAGEMENT_LINK_ENCRYPTION_KEY_V1` — Cloudflare Worker secret olarak kalıcıdır. İlk deploy'da bootstrap edilir, sonraki deploy'larda değeri okunmadan korunur.
- `NOTIFICATION_FROM_EMAIL` — `randevu@notify.kepenk.ai` metadata'sıdır.

## Test verisi ve reset

Workflow iki sahte tenant kullanır:

- `Staging Salon A` / `staging-salon-a`
- `Staging Salon B` / `staging-salon-b`

Her tenant ayrı owner membership, hizmet, personel, staff-service eşleşmesi, çalışma saatleri ve public booking ayarı taşır. Production müşteri/personel verisi fixture'a kopyalanmaz.

Tekrarlanabilir komutlar:

```bash
npm run staging:config
npm run staging:reset
STAGING_OWNER_A_ID=<uuid> STAGING_OWNER_B_ID=<uuid> npm run staging:seed
npm run staging:smoke
```

Migration deploy:

```bash
supabase db push --db-url "$STAGING_DATABASE_URL" --include-all --yes
```
