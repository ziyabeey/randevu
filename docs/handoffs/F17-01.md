Durum: **Repo-side hazırlık main'de; gerçek Supabase staging kuruldu ve ACL hardening canlıda doğrulandı; canlı kabul dış credential provisioning'i nedeniyle engelli.** Cloudflare + Resend + gerçek staging workflow/smoke zinciri doğrulanmadan `Tamamlandı` sayılmaz.

## Repo tarafında hazır olanlar

- Cloudflare `staging` environment sözleşmesi ve `npm run build:staging`.
- Manual `Staging deploy` GitHub Actions workflow'u.
- Supabase migration push sırası.
- Server-side test Auth owner bootstrap'ı.
- İki sahte işletmeli tenant-safe staging fixture, reset ve acceptance SQL'i.
- Notification/public-booking server secret hash provisioning.
- Gerçek Worker API zinciri için staging smoke: health → login → session → business select → catalog.
- Secret değerleri repo/PR/handoff içine yazılmaz; workflow yalnız dış secret isimlerini sözleşme olarak taşır.
- CI hosted Supabase'in `extensions` pgcrypto yerleşimini, API rol grant'lerini ve function default ACL davranışını taklit eder.
- Staging Supabase ref/URL, mevcut Worker ile uyumlu public anon key ve fixture owner email'leri workflow metadata'sıdır.
- Owner parolaları her run'da rastgele üretilip GitHub masking'e eklenir.
- `PUBLIC_BOOKING_GATE_SECRET` ve `NOTIFICATION_DISPATCH_SECRET` her staging run'ında rastgele üretilir, maskelenir, aynı job içinde DB hash provisioning + Worker runtime'a birlikte bağlanır.
- `MANAGEMENT_LINK_ENCRYPTION_KEY_V1` özellikle **kalıcı dış secret** olarak tutulur; mevcut recovery ciphertext'lerinin çözülebilirliği korunur.
- `STAGING_APP_ORIGIN` elle girilmez; generated Wrangler Worker adı + Cloudflare account Workers subdomain'i üzerinden workflow içinde türetilir.
- Cloudflare origin lookup DB migration/fixture adımlarından önce çalışır; geçersiz Cloudflare erişiminde staging DB'ye dokunulmaz.
- Dışarıdan provision edilmesi gereken değer sayısı tarihsel 17'den önce 11'e, sonra 9'a, şimdi **7'ye** düşürülmüştür.

## Security advisor sınırı

- `RLS enabled but no policy` INFO kayıtları capability/outbox/config/rate-limit tablolarındaki bilinçli deny-all doğrudan tablo modelidir; tek başına açık sayılmaz.
- Server-secret veya opaque capability ile bilinçli anon EXECUTE verilen SECURITY DEFINER wrapper'lar advisor tarafından genel uyarı olarak listelenebilir; kabul, explicit ACL matrisi + uygulama secret/token kontrolüne dayanır.
- `btree_gist` extension'ın `public` şemasında olması ayrı bir advisor uyarısıdır. Bu F17-01 ACL blocker'ında extension relocation yapılmaz.
- `touch_updated_at` mutable search_path blocker'ı PR #18 ile kapanmıştır.
