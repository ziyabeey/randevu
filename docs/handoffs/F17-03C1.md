## Run

```sh
npm run build
npm run test:public-bundle
```

Canonical `scripts/ci-code.mjs` already runs the public-bundle command after the production build. The same command now also prints `F17_ROUTE_BUNDLE` summaries and a full JSON `F17_ROUTE_BUNDLE_RECEIPT`. Missing/invalid inputs fail the command, rather than producing a zero-byte success.

Vite's `.vite/manifest.json` supplies imports, dynamic imports and CSS references. The reporter verifies the HTML entry matches the manifest, follows static import edges including cycles, and counts each actual output file once per selected surface. It records raw/gzip bytes and SHA-256 values for the manifest, HTML and measured assets. The checkout is read with `git rev-parse HEAD`; unresolved identity stays null, not an environment-variable guess.

Surfaces:
- Public booking `/r/:slug`.
- Workspace shell before the authenticated outlet.
- Authenticated calendar `/app/calendar`.
- SalonApp `/app/mobile`.

Shared CSS is listed explicitly. The sum is individual gzip-level-9 compressed files, not one combined archive or a measured CDN transfer size.

## Evidence limits

The receipt is the selected lazy entries plus their static build closure. It is NOT a browser request trace, a full interaction/locale graph or a latency/real-device measurement. Unselected dynamic children, fonts, images, video and API payloads are not counted. Vite's chunk manifest does not identify every source module co-located inside a chunk; it cannot alone prove marketing isolation.

Marketing remains `NOT_MEASURED` until MKT-01's accepted entry/root cutover is available. Existing marketing manifest keys and any keys in a measured closure are listed, but presence/absence does not become full route acceptance. No arbitrary workspace/CSS budget or new feature blocker is introduced.

Auth/session hop count, calendar p50/p95 and waterfall, marketing root cutover/browser isolation, DB/Storage restore, provider acceptance and the real-business pilot remain outside this child.
