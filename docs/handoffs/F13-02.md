## Frozen scope

F13-02 completes the existing Phase 13 contract without pulling F13-03/F13-04 forward:

1. Day, week and list presentations use the same canonical group-aware `/api/calendar` payload for the same date/staff range.
2. Day keeps physical service-line geometry across staff columns; list collapses physical lines into one logical reservation row with service/staff summary.
3. Direct date, Today and staff filters are explicit; list can preserve either a one-day or seven-day range.
4. Staff identity has a deterministic accent separate from appointment status. Status remains written text and is never color-only.
5. A current-time line appears only on the business-local current day and only inside the visible day-grid range.
6. Long customer/service/staff text wraps or truncates without widening the layout.
7. The S07 date-range carry-forward is closed separately in the paginated booking API: business-local inclusive-start / exclusive-end range, range-bound opaque cursor, and exact old-RPC authority closure.

## DST acceptance

`supabase/tests/f13_booking_date_range.sql` uses `America/New_York` on **2026-11-01**, a DST fall-back day.

For local range `[2026-11-01, 2026-11-02)` it proves:
- just-before local midnight excluded;
- exact local midnight included;
- both distinct repeated `01:30` instants included;
- late local-day appointment included;
- exact next local midnight excluded;
- pagination continuation stays inside the same range/revision;
- unbounded compatibility still works;
- half/reversed range fails closed;
- recovery session denied;
- v2 grant closed and exact v3 authenticated grant present.

The PostgreSQL plan executes the new range migration/test on both `yzt_test` and the `yzt_s08_upgrade` upgrade lane.
