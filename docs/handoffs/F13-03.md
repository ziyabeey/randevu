## Frozen scope

F13-03 consumes the accepted booking/group/customer/availability authorities rather than starting a second booking engine.

1. Operator create order is **Time → Customer → ordered service/staff lines → Note → Create**.
2. One or many service lines use the same server group planner/create transaction.
3. Create carries one idempotency key for the whole group; collision/partial-write authority remains server-side.
4. A guarded close-time action sits next to booking creation and uses the existing availability-block API.
5. Existing group/line reschedule and cancellation remain the movement/cancellation authority.
6. Native group lifecycle adds one atomic CAS/idempotent status RPC for `scheduled → confirmed → completed|no_show`.
7. Partial/cancelled/native groups are not flattened into a false terminal status.
8. Detail exposes customer/time/note/service lines and supported actions.
9. Future **Fotoğraf** and **Adisyon** connection points remain visible but disabled/informational until F16-03/F14.
10. Repeat/SMS remain explicit F16-01/F16-02 future hints, not fake controls.
