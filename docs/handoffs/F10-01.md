## Uygulanan sözleşme

- Access token her istekte Supabase Auth üzerinden doğrulanır; geçersiz access cookie varsa refresh tokenla yenileme denenir.
- Refresh başarısızsa access/refresh/business/recovery cookie'leri temizlenir.
- Aktif işletme üyeliği cookie iddiasından değil her session/catalog isteğinde güncel `memberships` kaydından doğrulanır; silinen/pasif üyelik seçili işletme cookie'sini düşürür.
- Session tokenları yalnız HttpOnly cookie'de tutulur; API cevap gövdesi veya URL fragment/query'sine yazılmaz.
- Browser mutation'ları exact same-origin + `Sec-Fetch-Site` ve HttpOnly-cookie/memory-header double-submit CSRF kontrolünden geçer.
- Signup/recovery PKCE verifier yalnız kısa ömürlü, bounded HttpOnly flow cookie'sinde tutulur; auth code server-side değiştirilir ve state replay'i reddedilir.
- Token-hash doğrulama yanlış/süresi dolmuş/tekrar kullanılan bağlantılar için tek generic `AUTH_LINK_INVALID` cevabı verir.
- Recovery oturumu yalnız session, logout ve password update yüzeyinde kalabilir; işletme ve randevu feature API'leri `PASSWORD_UPDATE_REQUIRED` ile fail-closed durur.
- Parola değişiminde global sign-out çağrısı yapılır, local session cookie'leri kesin olarak temizlenir.
