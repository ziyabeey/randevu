### Korunan sözleşme

- Ortak auth sonucu: geçersiz/bitmiş ve yenilenemeyen session `401 AUTH_REQUIRED`; aktif kullanıcı fakat geçersiz/olmayan seçili üyelik `403 TENANT_REQUIRED`; geçici Supabase/Auth arızası `503 AUTH_UNAVAILABLE` ve geçerli session cookie'leri korunur.
- Recovery session S01 sınırını korur ve feature API'lerinde `403 PASSWORD_UPDATE_REQUIRED` alır.
- Refresh rotation yalnız ortak helper üzerinden yapılır; feature dosyalarında access/refresh cookie yazma veya silme kalmaz.
- Cookie tabanlı her unsafe API isteği exact application `Origin` ve double-submit CSRF ister. `Origin`/`Sec-Fetch-Site` başlıklarının ikisinin de yokluğu guard'ı atlatmaz.
- Public booking create/recovery ve capability manage uçları auth-cookie yetkisine dayanmadıkları için açık, dar istisna olarak envanterlenir. Capability bearer URL query/path'e taşınmaz. Public abuse/idempotency ve capability doğrulaması korunur.
- Safe `GET/HEAD/OPTIONS` istekleri mutation guard'a girmez. Scheduled/provider işlemleri browser route'u gibi değerlendirilmez.
- İş kuralları, veri modeli, RPC isimleri, hata metinleri ve idempotency anlamı gereksiz yere değiştirilmez.

## İlk route / guard matrisi

| Sınıf | Örnek | Mutation koruması |
| --- | --- | --- |
| Cookie-auth | auth POST/PUT, business select/create, service/staff, booking operator, availability, public settings | Exact Origin + CSRF zorunlu |
| Public booking | `/api/public/business/:slug/book`, `/api/public/booking/recover` | Dar istisna; public abuse + proof/idempotency korunur |
| Capability manage | `/api/manage/view`, `/slots`, `/reschedule`, `/cancel` | Dar istisna; body capability + idempotency korunur |
| Safe read | GET/HEAD/OPTIONS | Guard yok; auth gereken yerde ortak require helper devam eder |
| Server/scheduled | Worker scheduled dispatcher | Browser mutation guard kapsamı dışında |

Bu matris uygulama ve test sırasında tam route envanteriyle doğrulanacak; bilinmeyen unsafe `/api/*` yolu güvenli varsayılan olarak cookie-auth sınıfına düşecek.

## Kabul planı

1. Eski feature helper'larıyla Supabase `/auth/v1/user` 503 ve membership 503 davranışını kırmızı HTTP testleriyle göster.
2. Dört feature Worker'ı ortak `AuthEnv`, `supabaseRequest`, `readJson`, `first`, `requireMember` ve `canManage` yardımcılarına taşı.
3. Bütün unsafe API yolları için fail-closed mutation sınıflandırması ekle; eksik Origin, yanlış Origin, cross-site fetch ve yanlış/eksik CSRF negatiflerini doğrula.
4. Public booking ve capability istisnalarının yalnız kendi dar yollarında çalıştığını, bilinmeyen unsafe route'un istisna kazanmadığını test et.
5. Yerel frontend fetch yardımcılarını `src/api.ts` üzerine taşı; CSRF yenileme, credentials ve hata kodları ortaklaşsın.
6. Expired access + refresh rotation, membership iptali, recovery session ve normal login/logout/password gerilemelerini çalıştır.
7. Base staging smoke'un yeni Origin/CSRF sözleşmesiyle gerçek hosted ortamda geçmesini sağla; S02 için ayrı opt-in gerekirse dar acceptance girdisi ekle.
8. Audit, typecheck, production/staging build, browser smoke, HTTP ve PostgreSQL/F09 zinciri yeşil olmadan merge etme.
