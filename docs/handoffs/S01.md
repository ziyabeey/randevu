## Doğrulanan kusur

Önceki uygulama recovery yetkisini yalnız 15 dakikalık `yzt_password_recovery` marker cookie'sinden okuyordu; refresh cookie'si ise 30 gün yaşayabiliyordu. Marker silindiğinde, bozulduğunda, süresi dolduğunda veya geçersiz confirmation tarafından temizlendiğinde canlı recovery access/refresh session normal session gibi yorumlanabiliyordu.

Kusur önce `tests/s01-recovery-session-boundary.test.mjs` ile görünür hale getirildi. CI `34691808686` beklenen biçimde kırmızı oldu:

- marker'sız recovery katalog isteği `TENANT_REQUIRED` döndürdü,
- sahte marker normal password session'ı recovery'ye düşürdü,
- refresh recovery sınıfını kaybetti,
- geçersiz confirmation mevcut recovery session'ı genişletti.

## Uygulanan sözleşme

### Doğrulanmış session authority

- `worker/auth.ts`, access tokenı önce Supabase `/auth/v1/user` ile doğrular; ardından aynı bearer'ın JWT payload'ındaki `sub`, `session_id` ve `amr` alanlarını fail-closed ayrıştırır.
- JWT subject ile Supabase user kimliği eşleşmeden session kurulmaz.
- `amr.method = recovery`, recovery authority'nin sunucu kaynaklı gerçeğidir.
- Refresh sonucunda dönen yeni access token aynı biçimde doğrulanır; recovery sınıfı refresh ve ikinci sekmede korunur.
- Eksik/bozuk session claims veya subject uyuşmazlığı yetki vermez; refresh de güvenli session üretemezse cookie'ler temizlenir.

### Marker ve route davranışı

- `yzt_password_recovery` artık yetki kaynağı değil, doğrulanmış session sonucundan onarılan/kaldırılan HttpOnly kullanıcı arayüzü ipucudur.
- Marker silinmiş veya bozulmuş recovery session'da yeniden yazılır.
- Normal password session'a sahte marker eklenirse marker kaldırılır ve normal session recovery sayılmaz.
- Geçersiz token-hash confirmation mevcut recovery marker/session'ını temizleyerek yetki genişletemez.
- Signup/login/PKCE callback/token-hash confirmation, kurduğu session'ın recovery/non-recovery sınıfının beklenen akışla eşleşmesini doğrular.
- `worker/app.ts`, availability/booking/calendar/public-settings router'larını marker yerine doğrulanmış ortak session sonucuyla fail-closed sınırlar.
- Parola güncellemesi global sign-out çağrısını dener ve aktif browser session cookie'lerini kesin temizler; eski recovery bearer geçerliyse yalnız recovery olarak kalabilir, normal yetkiye dönüşemez.

## Geçiş tablosu

| Durum | Authority sonucu | Beklenen erişim |
| --- | --- | --- |
| Verified recovery AMR + marker var | Recovery | Yalnız session/logout/password update |
| Verified recovery AMR + marker yok/bozuk/expired | Recovery, marker onarılır | Protected feature API'leri `PASSWORD_UPDATE_REQUIRED` |
| Verified recovery AMR + refresh | Recovery | Sınır korunur |
| Verified recovery AMR + ikinci sekme | Recovery | Sınır korunur |
| Verified password AMR + sahte marker | Normal, marker kaldırılır | Güncel membership yetkisi uygulanır |
| Invalid/replay confirmation + mevcut recovery session | Recovery değişmez | Yetki genişlemez |
| Password update sonrası eski recovery bearer | Rejected veya recovery | Hiçbir zaman normal feature yetkisi kazanmaz |
| Claim/session/user uyuşmazlığı | Session kurulmaz | Fail-closed |
