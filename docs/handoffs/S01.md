## İlk doğrulanan bulgu

Mevcut kod `yzt_password_recovery` marker'ını 15 dakika tutarken refresh cookie'sini 30 gün tutuyor. `resolveAuth()` recovery durumunu yalnız bu marker'dan okuyor. Ayrıca geçersiz token-hash confirmation marker'ı temizleyip canlı recovery access/refresh cookie'lerini bırakabiliyor. Böylece marker eksik olduğunda aynı recovery session normal session gibi yorumlanabiliyor.

Supabase Auth güncel session modelinde recovery giriş yöntemini session AMR kaydında ve JWT `amr` claim'inde taşır; refresh aynı session bağlamını sürdürür. En küçük güvenli çözüm önce bu sunucu kaynaklı bağlamı mevcut HttpOnly token doğrulamasına bağlayıp marker'ı yalnız onarılabilir bir ipucu haline getirmektir. Bu varsayım repo testleri ve gerçek hosted token ile doğrulanmadan kabul edilmeyecektir.

## Kabul planı

1. Marker silinmiş, bozulmuş ve süresi dolmuş recovery cookie jar'ı protected API'lerde `PASSWORD_UPDATE_REQUIRED` alır.
2. Aynı recovery session access refresh'inden sonra recovery kalır.
3. Geçersiz ve replay confirmation mevcut recovery jar'ını normal yetkiye yükseltmez.
4. Normal password session'a sahte recovery marker eklenmesi normal session'ı recovery yapmaz.
5. İkinci sekme ve parola güncellemesi sonrası eski bearer davranışı test edilir.
6. Normal login/logout/password change gerilemeleri geçer.
7. Repo CI yeşil olur.
8. Public recovery isteği → test mailbox → redirect/PKCE callback → password update → login zinciri gerçek staging'de geçmeden görev `Tamamlandı` sayılmaz. Admin `generate_link` doğrudan confirmation tek başına bu canlı kabulün yerine geçmez.
