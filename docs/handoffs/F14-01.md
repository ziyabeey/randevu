## Delivered boundary

KolayApp is a private mobile surface on the existing workspace authority. It does not own a second auth/session/business model, booking engine, customer engine, HTTP client or tenant model.

Canonical route map:

| Route | Surface |
| --- | --- |
| `/app/mobile` | Randevular |
| `/app/mobile/appointments` | Randevular alias |
| `/app/mobile/tickets` | Adisyonlar |
| `/app/mobile/new` | Yeni |
| `/app/mobile/customers` | Müşteriler |
| `/app/mobile/more` | Diğer |

Browser history owns tab state through these URLs. The five fixed tabs remain:

`Randevular / Adisyonlar / Yeni / Müşteriler / Diğer`.

## Reused authorities

- `WorkspaceShell` remains the only private session/business gate.
- `WorkspaceProvider` / `useWorkspace()` provide the selected business and verified membership.
- Business switching still uses `POST /api/businesses/select` through the accepted workspace selector and preserves the active KolayApp tab after verification.
- Randevular renders the existing `CalendarPage`.
- Müşteriler renders the existing `CustomersPage`.
- Existing `api()`, CSRF/workspace coherence and scope-epoch behavior remain unchanged.

No migration, DB contract, Worker endpoint or new authentication path belongs to F14-01.

## Fail-closed future connections

F14-01 exposes the navigation shape without pretending later modules exist.

- **Adisyonlar:** informational/unavailable until F14-02/03/04 provide real server authority.
- **Yeni:** only Yeni randevu is live through the existing booking flow. Adisyon, product sale, package sale and expense remain disabled.
- **Diğer / reports:** cash, commissions, expenses, product sales, income/expense and detailed staff reports remain disabled until their owning phases.
- **Diğer / setup:** existing accepted setup/team/services/availability/public-booking pages are linked. Product/stock and promotions remain disabled.
- Service-photo and feedback/support modules remain unavailable until their owning work is accepted.

## Mobile acceptance

Required real-browser evidence is embedded in the existing F13 workspace Chrome fixture so the new surface is tested against the same session/business/calendar/customer authority.

Acceptance covers:

- 390 px and 360 px viewport behavior;
- bottom-nav order and touch targets;
- safe viewport placement and reduced-height/keyboard-like viewport behavior;
- Randevular and Müşteriler using the same business data;
- no extra session authority when changing tabs;
- browser back/forward restoring tab URLs;
- business switch remounting the selected tab under the verified tenant;
- unavailable Adisyon copy not claiming payment success.

The existing F13 workspace/browser acceptance remains part of the same required suite.
