## Stabilization sözleşmesi

`docs/plan/stabilization.md#s08` bulgusu mevcut tenant izolasyonunun bozuk olduğunu iddia etmez. Açık, gelecekte `public` gibi exposed schema içinde `postgres` migration rolüyle yaratılan yeni **table/view, sequence ve function** nesnelerinin varsayılan object ACL'lerini fail-closed doğrulayan kapının eksik olmasıdır.

S08 ile RLS ve object privilege iki ayrı katman olarak korunur:

- Yeni table/view ve sequence, `anon` veya `authenticated` için otomatik object privilege kazanmaz.
- Yeni function, PostgreSQL'in `PUBLIC EXECUTE` varsayılanı ve hosted Supabase'in schema-scoped API-role varsayılanı açısından kapalı kalır.
- Erişim ancak bilinçli `GRANT` ile açılır; table/view satır erişiminde ayrıca uygun RLS policy gerekir.
- `SECURITY DEFINER` probe açık API yüzeyi yapılmaz.
- S04 sonrası gerçek public-booking/business-create RPC daraltması ve S03 sonrası server-secret-gated notification dispatch yüzeyi regresyon testinde korunur.

K01–K03 ve mevcut router davranışı değişmez. Birleştirilmiş migration dosyaları değiştirilmez; yalnız ileri S08 migration eklenir.

## Uygulama

### İleri migration

`supabase/migrations/20260913201500_s08_db_object_access_gate.sql`

`postgres` rolünün `public` schema geleceği için:

- tables üzerindeki `anon, authenticated` default privileges kaldırılır; PostgreSQL `ON TABLES` kapsamı view'ları da içerir,
- sequences üzerindeki `anon, authenticated` default privileges kaldırılır,
- functions için hem global `PUBLIC EXECUTE` hem schema-scoped `anon, authenticated EXECUTE` default'u kapatılır.

Migration mevcut nesnelerin ACL'sini yeniden yazmaz; yalnız sonradan oluşturulacak nesnelerin varsayılanını değiştirir. `service_role` varsayılanları bu dar S08 kabulünde değiştirilmez.

### Disposable negatif / pozitif erişim testi

`supabase/tests/s08_db_object_access_gate.sql`

Test vanilla PostgreSQL'in doğal kapalı table/sequence varsayılanından yanlış yeşil almamak için önce eski hosted proje davranışını yalnız disposable gelecek nesneler için yeniden kurar, sonra gerçek S08 migration'ı tekrar uygular.

Kanıt matrisi:

1. İki Business ve owner/staff Membership fixture'ı transaction içinde kurulur.
2. Disposable table + identity sequence + `security_invoker` view + invoker function + `SECURITY DEFINER` function yaratılır.
3. Explicit grant öncesi anon/authenticated için table/view/sequence/function erişimi negatiftir.
4. Yalnız authenticated probe yüzeyine bilinçli grant verilir; definer kapalı kalır.
5. Tenant A owner kendi Business satırlarını okur/yazar; tenant B satırı görünmez ve tenant B INSERT RLS tarafından reddedilir.
6. Tenant A staff kendi tenant satırlarını okuyabilir ama `can_manage_business()` kullanan manager-only INSERT policy'sini geçemez.
7. `security_invoker` view aynı tenant RLS sınırını korur.
8. Anon bütün probe nesnelerinde object-grant katmanında reddedilir.
9. Owner/BYPASSRLS kabul kanıtı olarak kullanılmaz.
10. Fixture ve disposable nesneler transaction sonunda rollback olur.

### S04 sonrası güncel ACL regresyonu

`supabase/tests/s08_post_s04_acl_regression.sql`

İlk S08 CI koşusu `34771836442`, S08 future-object ve tenant/rol probe'larından sonra tarihsel `f17_hosted_acl_hardening.sql` testini yeniden çalıştırdığı için kırıldı. İlk somut hata, S04'ün kasıtlı olarak kapattığı `public.create_business_with_owner(text,text,text)` için F17 dönemindeki authenticated EXECUTE beklentisinin artık false olmasıydı.

Düzeltme, F17 tarihsel kabul testini değiştirmez. O test CI'da F17 migration'ının hemen ardından kendi tarihsel yerinde kalır. S08 final zincirinde bunun yerine güncel post-S04 matris doğrulanır:

- `create_business_with_owner` iki API rolüne kapalı,
- `create_business_with_owner_guarded` yalnız authenticated,
- `execute_public_operation` yalnız anon transport,
- eski token-management ve per-operation guarded public-booking RPC'leri iki API rolüne kapalı,
- notification v1 claim/complete/release kapalı,
- notification v2 claim/lock/complete/release ve maintenance yalnız anon transport,
- dispatch/gate/quota helper'ları iki API rolüne kapalı.

Böylece public booking ve notification yüzeyi S03/S04 son durumuna göre gerileme kontrolü alır.

## Local ve hosted migration rolü farkı

Yerel CI bootstrap, hosted Supabase'in function default grant davranışını modeller. Vanilla PostgreSQL table/sequence için aynı permissive Supabase proje varsayılanını kendiliğinden üretmediğinden S08 testi yalnız kendi disposable geleceği için eski hosted table/sequence default ACL'lerini geri kurar ve gerçek migration'ı yeniden uygular. Böylece eski nesnelerin ACL'si değiştirilmeden hosted migration rolü (`postgres`) davranışı test edilir.

### Hosted staging salt-okunur envanter kanıtı

`randevu-staging` projesinde yalnız metadata sorguları çalıştırıldı; DDL veya veri yazımı yapılmadı.

- `current_user = postgres`, `session_user = postgres`: migration default ACL hedef rolü canlı ortamla eşleşiyor.
- `pg_default_acl`, `postgres/public` future table varsayılanında `anon`, `authenticated` ve `service_role` grant'larının; future sequence varsayılanında aynı roller için `rwU` yetkilerinin hâlâ bulunduğunu gösterdi.
- Function tarafında F17 hardening görünür: global default yalnız `postgres=X`; `public` schema function default'unda anon/authenticated yok, `service_role` explicit EXECUTE kalıyor.
- `public` içindeki 23 normal tablonun 23/23'ünde RLS + FORCE RLS açık. Anon SELECT grant sayısı 0; authenticated SELECT grant sayısı 13.
- `public` içinde sequence yok; sequence riski gelecekteki migration nesnesi kapısıdır.

Bu envanter S08 migration'ın mevcut object ACL'lerini topluca değiştirmemesi, yalnız **future default privileges** üzerinde çalışması kararını doğrular.
