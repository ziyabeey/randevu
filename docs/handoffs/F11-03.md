## Kapatılan R2 blocker'ları

### 1. Calendar / Booking / Customers artık gerçek group consumer

Native multi-line rezervasyon tek logical booking olarak tüketilir.

**Calendar**

- fiziksel service-line geometri korunur;
- özet sayıları `group_id` kökünde sayılır;
- native satıra tıklanınca canonical `GET /api/bookings/groups/:groupId` projection'ı yüklenir;
- drawer tam group satırlarını, authoritative group version/status/start/end bilgisini kullanır;
- whole-group mutation appointment-id legacy yoluna düşmez;
- personel filtresi yalnız geometriyi etkiler; farklı personele dağılmış sibling line'lar drawer'da kaybolmaz;
- canonical group detail okunamazsa native mutation açılmaz, fail-closed kalır;
- legacy single appointment eski mutation yüzeyini aynen kullanır.

**BookingPage**

- current app `GET /api/bookings/groups` group-rooted projection'ını tüketir;
- native group tek üst seviye rezervasyon kartıdır, ordered lines kartın içindedir;
- whole-group reschedule/cancel optimistic `version` taşır;
- line-local cancel/service-change/schedule-edit aynı group CAS authority'yi kullanır;
- legacy single status/reschedule/history endpointleri korunur.

**CustomersPage**

- current app `/api/customers/:id/group-history` kullanır;
- bir rezervasyon tek history entry'dir;
- ordered service lines aynı entry içinde gösterilir;
- legacy single bir service-line'lı group projection olarak görünür ve tarihsel snapshot anlamı korunur.

### 2. Customer history pagination group-rooted ve atomik

Eski physical-line cursor `(starts_at, appointment_id)` current browser contract'ından çıkarıldı.

Yeni bounded RPC'ler:

- `list_business_booking_groups_page_v3(...)`
- `list_business_customer_booking_groups_page_v3(...)`

Cursor `(group_starts_at, group_id)` kökündedir. Böylece sibling service-line'lar iki sayfaya bölünmez, bir logical booking sonraki sayfada tekrar etmez.

Worker cursor kind'ları ayrıca ayrıldı:

- `booking_groups`
- `customer_group_history`

Legacy physical-line cursor yeni group endpointinde kabul edilmez.

### 3. F11-01 line-local carry-forward tamamlandı

F11-01'in bağlayıcı devir maddeleri explicit authority ile kapatıldı.

**Line cancel**

- mevcut `cancel_appointment_group_line(...)` group version'ı ilerletir;
- sibling line status/time/snapshot'ı değiştirmez;
- partial aggregate semantiği korunur.

**Line service change**

- `change_appointment_group_line_service(...)`
- exact group + exact line + idempotency + expected group version ister;
- active same-tenant service ve staff eligibility doğrulanır;
- mixed currency fail-closed;
- frozen finansal/catalog snapshot yeni authoritative service row'dan birlikte freeze edilir;
- yalnız mevcut duration/buffer/processing footprint ile birebir uyumlu replacement line-local değişebilir;
- scheduling footprint değişiyorsa `BOOKING_GROUP_LINE_REPLAN_REQUIRED`, sibling'ları gizlice yeniden planlama yok;
- F11-01 immutability yalnız exact transaction-local line authority için dar biçimde açılır, genel update authority oluşmaz.

**Line schedule edit**

- `reschedule_appointment_group_line(...)`
- expected group version ile deterministic CAS;
- staff eligibility, çalışma saatleri, blocks, external appointment conflict ve sibling overlap doğrulanır;
- same-staff collapsed occupancy run'da sibling occupancy rewrite gerekecekse group replan zorunlu;
- sibling satır byte-semantics korunur;
- stale write `BOOKING_GROUP_VERSION_CONFLICT` verir.

HTTP yüzeyi:

- `POST /api/bookings/groups/:groupId/lines/:lineId/service`
- `POST /api/bookings/groups/:groupId/lines/:lineId/reschedule`
- mevcut line cancel route

Yeni unsafe route'lar S02'nin Origin/CSRF/provenance mutation envanterine eklenmiştir; public/capability exception kazanmazlar.

### 4. Gerçek ekran browser acceptance

Fixture yalnız API'dir; mount edilen component'ler production component'leridir.
