## Teslim edilen mimari

- F09-02 recovery kaydı appointment'a bağlandığı anda DB trigger e-posta varsa durable notification job üretir. Trigger aynı outer booking transaction'ında çalıştığı için appointment + capability + recovery + notification intent tek commit sınırındadır.
- Booking HTTP yolu provider çağrısı beklemez. Provider arızası appointment'ı rollback etmez.
- Job state machine: `pending -> leased -> sent`; retryable hata `leased -> retry_wait -> leased`; kalıcı/bütçe aşımı `-> failed_terminal`.
- Claim `FOR UPDATE SKIP LOCKED` kullanır. Lease varsayılanı **45 saniye**, batch üst sınırı 50, Worker şu anda batch başına 10 job ister.
- Provider timeout **10 saniye**. Maksimum deneme **8**.
- Backoff sırası: **1 dk, 5 dk, 15 dk, 1 saat, 4 saat, 12 saat, 24 saat**; retry penceresi en fazla **72 saat** ve F09-02 recovery TTL'ini aşmaz.
- `NOTIFICATION_DISPATCH_SECRET` en az 256-bit Worker secret'ıdır. DB `notification_dispatch_config` yalnız SHA-256 hash'ini tutar. Claim/complete/release/maintenance RPC'leri doğru secret olmadan çalışmaz.
- Public/anon tabloları okuyamaz. `sent` authoritative kaydı yalnız aktif lease + dispatch secret ile `complete_notification_job` üzerinden yazılır; idempotency key bilen müşteri sahte receipt yazamaz.
- Management bearer job payload'ında veya plaintext DB alanında yoktur. Dispatcher F09-02 AES-256-GCM ciphertext'ini yalnız bellekte decrypt eder ve `/m#<token>` linkini provider isteği hazırlanırken üretir.
- `PUBLIC_APP_ORIGIN` production'da HTTPS olmak zorundadır; HTTP yalnız localhost/127.0.0.1/::1 geliştirme için kabul edilir.
- Cron Cloudflare Worker tarafından dakikada bir çalışır. Önce maintenance, sonra dispatch yapılır. Provider config eksikse dispatch job claim etmez; maintenance dispatch-secret mevcutsa retention/terminalization yapmaya devam edebilir.

## Provider ve teslim semantiği

Provider: **Resend REST API**. SDK eklenmedi.

- Stable provider idempotency key: `public-booking-confirmation/<appointment_id>`.
- Provider isteği kabul edip HTTP cevabı kaybolursa job retry edilir ve aynı idempotency key tekrar kullanılır.
- Resend'in güncel idempotency saklama penceresi **24 saat**tir. Bizim bounded retry penceremiz 72 saate kadar uzayabildiği için 24 saat sonrası ambiguous retry'larda mutlak exactly-once teslim garantisi verilmez.
- DB state `sent`, **provider'ın isteği kabul edip bir provider message ID döndürdüğü** anlamına gelir. Müşterinin inbox'ına teslim edildiği anlamına gelmez. Gerçek provider/staging teslim kanıtı F09-05/F17 kapsamındadır.

## Retry sınıflandırması

Retryable:

- HTTP 408
- HTTP 429 (`Retry-After` dikkate alınır)
- HTTP 5xx
- network error
- 10 saniyelik timeout
- Resend `concurrent_idempotent_requests`

Genel 4xx/provider validation hataları terminal kabul edilir. Her terminal veya geçici notification hatasında appointment yaşamaya devam eder.
