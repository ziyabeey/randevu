## Teslim edilen kapsam

- Public booking + management capability + recovery bootstrap tek PostgreSQL transaction sınırına alındı.
- Management bearer ve recovery secret Worker'da SHA-256 hashleniyor; plaintext değerler PostgreSQL'e gönderilmiyor.
- Management bearer AES-256-GCM ile `MANAGEMENT_LINK_ENCRYPTION_KEY_V1` kullanılarak şifreleniyor; ciphertext/IV/key version recovery kaydında tutuluyor.
- Encryption key eksik/bozuksa DB create çağrısı yapılmadan `BOOKING_RECOVERY_UNAVAILABLE` / HTTP 503 ile fail-closed davranılıyor.
- `/api/public/booking/recover`, `recoveryId + idempotencyKey + recoverySecret` kanıtını doğrulayıp aynı appointment sonucunu ve `/m#<token>` linkini geri üretiyor.
- UI pending recovery kaydında yalnız slug, idempotency key, recovery ID/secret, request fingerprint ve timestamp tutuyor; müşteri PII'si ve management token sessionStorage'a yazılmıyor.
- Belirsiz network sonucunda UI yeni booking key üretmiyor; önce recovery deniyor.
- Eski Faz 7 `/m#token` capability akışı ve manage endpoints korunuyor.

## Test / kabul kanıtı

Final code head incelemesinde mevcut PR CI `516a73aa31f04434d770e4d85528497ee5ac833e` için success durumda.

Kapsanan regression'lar:

- SQL: atomik create + capability, same-intent retry, changed recovery secret/ID conflict, yanlış proof generic not-found, duplicate management bearer rollback, plaintext secret saklanmaması, TTL expiry/cleanup.
- SQL concurrency: iki fiziksel PostgreSQL session; create transaction recovery advisory lock'ını tutarken recovery çağrısı commit'i bekliyor ve tek mevcut sonucu görüyor.
- HTTP: encryption config yoksa DB'ye gitmeden fail-closed; Supabase'e yalnız hash/ciphertext gönderimi; ambiguous network failure için `BOOKING_RESULT_UNKNOWN`; valid recovery ile original manage link; wrong/expired proof için generic 404.
- CI: typecheck, production build, Node HTTP contract ve Faz 2→F09-02 migration/regression zinciri.
